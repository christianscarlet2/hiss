A field guide to your poker bot

Understanding Hiss

Hiss is a poker-playing robot — a heavily extended fork of OpenHoldem that watches a poker table on screen, reads it with OCR, thinks with a strategy written in OpenPPL, and clicks the buttons for you.

This page is your friendly tour of how the whole thing actually works, end to end: the loop that beats once every fraction of a second, the strategy "brains" it can switch between, the rulebook (the OHF) that holds your distilled poker knowledge, and the swarm of helper programs that watch, learn, and quietly make it better. Everything below is drawn from the real code in this project — nothing invented. We define each term the first time it appears.

green = the snake / strategy & engine red = the ghost / decisions & actions blue = symbols & data purple = the synapse harmonizer amber = knobs & warnings

AThe big picture: one heartbeat

Hiss runs a single repeating cycle called the heartbeat. A background thread (CHeartbeatThread) loops forever, pausing briefly between beats (the scrape_delay, normally 300 ms — allowed range 100–5000 ms). Each beat it runs one function, ScrapeEvaluateAct(), which walks the table through these stages. Watch the green pulse travel through them:

The heartbeat pipeline — scrape → OCR → symbols → OHF → click → telemetry

What each stage really does

  1. 1 · Scrape. Hiss captures the bitmap of the poker window (CLazyScraper::DoScrape → CScraper). It only re-reads the regions it needs each beat (cards, bets, balances, pot, buttons, names) using the coordinates in the active tablemap — the per-site layout file that says "the hero's first card is this rectangle." Tablemaps now live in the postgres hiss database.
  2. 2 · OCR. Optical Character Recognition turns the pixels into text and card values. The heavy lifting (Tesseract) runs in separate worker processes — you'll see one main Hiss.exe plus several Hiss.exe --ocr-worker children (typically 6). The main process ships each changed region's pixels down a pipe to a free worker and gets text back; unchanged regions are served from cache. (CScraper::PreOcrParallel, COcrWorker, CAutoOcr.)
  3. 3 · Symbols. The symbol engines (CEngineContainer::EvaluateAll) convert the raw table read into the hundreds of named values the strategy reasons about — things like prwin (your win probability), PotSize, nopponentsplaying, aggressorchair, and the made-hand flags (HaveTopPair, HaveFlush…). Equity (prwin) is a Monte-Carlo simulation that runs on its own thread (CIteratorThread, 20,000 iterations) so it never stalls the beat.
  4. 4 · OHF decision. This is the strategy. Crucially, the OHF is not evaluated on every heartbeat — it is consulted only when it's actually the bot's turn to act (ismyturn) and the read has settled into a "final answer" (cards known, the prwin iterator finished, enough stable frames). A once-per-turn latch makes sure it acts exactly once. See section C for what's inside.
  5. 5 · Click. The autoplayer (CAutoplayer::DoAutoplayer) translates the OHF's answer (Fold / Check / Call / RaiseBy / RaiseTo / RaiseMax) into a real mouse click on the matching button. It figures out which button is which by reading the button labels with OCR (CAutoplayerButton). To keep two Hiss instances that share one mouse from clicking at once, clicks are guarded by a named system mutex (CMyMutex).
  6. 6 · Telemetry. The same beat writes to a local postgres outbox (frames, decisions, symbols, the full OHF trace). A shipper sends it to the replay server so you can later time-travel through any hand and see exactly why Hiss did what it did.

The key timing idea

Stages 1–3 (and a scrape validator that sanity-checks the read) happen every single beat. Stages 4–5 — deciding and clicking — happen together, once, only on your turn. So "the bot is always looking, but only speaks when spoken to."

CHow the OHF works (the heart of Hiss)

The OHF is the OpenHoldem Formula file — the strategy. Your version ships as a folder of segments under .strategy_build/strategy/ that a build script concatenates into one master file, Release/ScarletBeast_PowerHoldem.ohf. It is a complete No-Limit Hold'em strategy distilled from two foundational texts — Negreanu's Small Ball and Brunson's Power Poker — reconciled with a wider library (Harrington, "Crushing the Microstakes," and more) and a discipline layer (Tao Te Ching, Sun Tzu) used as guiding citations.

OpenPPL: the language

OpenPPL (Open Poker Programming Language) is how the strategy is written. The whole thing is just functions made of WHEN rules. A few ideas to hold onto:

  • Function blocks. Each function starts with a header like ##f$preflop## and contains a list of rules. Functions can call other functions (f$flop calls f$flop_nobet), which is how the strategy is organized.
  • WHEN … RETURN/action … FORCE. Each rule is one line: a condition, then what to do if it's true. Actions are Fold, Check, Call, RaiseTo <bb> (raise to a total size), RaiseBy <pct>% (bet a fraction of the pot), or RaiseMax (jam all-in). RETURN x hands a value back to whatever called the function.
  • First match wins, top to bottom. The engine reads the rules in order and stops at the first one whose condition is true. So order is everything — the strongest, most specific cases go on top; WHEN Others is the catch-all fallback at the bottom.
  • One rule = one physical line. A WHEN line cannot wrap. This is a real gotcha when editing — the whole condition and action live on a single line.
  • No "not-equal" operator. OpenPPL has no !=. You phrase the negative as NOT (a = b) or restructure the rule.
  • Symbols. Built-in named values you test against: prwin, PotSize, AmountToCall, nopponentsplaying, HaveTopPair, InButton, Raises, aggressorchair…
  • Lists. Named hand ranges, e.g. ##listOpenBTN## contains the button open-raise hands. A rule like WHEN InButton AND listOpenBTN … is true when you're on the button holding a hand in that list.

Here is one real, annotated rule from the flop file so you can read the grammar:

WHEN f$HaveStrongMade AND (f$Opp_IsStation OR f$Opp_IsFish) AND explain_value_flop RaiseBy f$BetPctVsStation % FORCE
Read it as: "WHEN I have a strong made hand AND the opponent is a calling-station or a fish — bet big for value (a pot-sized bet, f$BetPctVsStation)." The explain_value_flop symbol at the tail prints a plain-English reason into the Decisions pane. FORCE means this is a committed action, not advice.

The street dispatch — a hand's journey

A hand of poker has four betting rounds, called streets: preflop, flop, turn, river. The engine evaluates the matching top-level function for whichever street you're on. Each one first checks for safety/overrides, then dispatches to a sub-function based on the situation. Press play to walk a hand through and see which functions fire:

The street walk — which f$ function fires

Inside each street the same shape repeats: a _nobet branch (nobody has bet to you — do you value-bet, c-bet, semi-bluff, or check?) and a _vs_bet branch (someone bet — do you raise, call, or fold?). Preflop instead dispatches by how many raises have happened: 0 raises → f$preflop_open, 1 raise → f$preflop_vs_raise, 2+ → f$preflop_vs_3bet, and very short stacks switch to f$preflop_pushfold (jam or fold).

The master knobs

A handful of functions act as dials that retune the whole profile. These are what you tweak to change the bot's personality without rewriting rules:

KnobWhat it does
f$StyleThe single biggest dial. 0 = Small Ball (Negreanu: small bets, ~2.5x opens, ~60% c-bets, pot control). 1 = Power Poker (Brunson: aggressive, ~pot-sized bets, ~80% c-bets, fast draws). 2 = Hybrid (default). The Terminal command /strategy smallball|power|hybrid retunes it live.
f$CbetFreqHow often Hiss continuation-bets with air as the preflop raiser. Tied to f$Style and modulated by the aggressor knobs (press harder in position, give up out of position vs an opponent who has the lead). Dialed down vs calling stations — bluffing a station just donates.
f$ConservativeKnob / f$AggressorKnob0/1/2 restraint and pressure dials driven by who holds the betting initiative across streets (section below). They tighten or loosen at the margin — they never double-fire the value or commitment lines.
f$SafeVsOppRangeYour rule: "if nothing in the opponent's represented range beats us, we are safe to proceed." It green-lights thin value and bluff-catches. The flip side, f$BeatenByOppRange, folds the marginal stuff.
f$FeelerBet / f$FeelerSizeThe information-gathering system — bet as large as you can while still controlling the pot, to learn where you stand. Detailed below.
f$SizeMultA global bet-size multiplier = ICM chip value × stack-depth proportionality. Every open/iso/3-bet/4-bet and post-flop bet is scaled by it, so sizing shrinks near a tournament bubble and grows when stacks are deep.

The inference layer: aggressor rhythm & "what are they representing?"

The file 12_aggressor.ohf is where Hiss reasons about the other player. It rests on two engine symbols that are remembered across streets: aggressorchair (the seat of the last raiser, −1 if none) and iamaggressor (1 if that's you). From these it builds two ideas:

  • Rhythm. When an opponent holds the initiative and you act before them (f$ActBeforeAggressor), the strong play is usually to let them do the betting — check and call good hands rather than lead into the player who has the lead. When you have the initiative and position, keep barreling. This is encoded as the conservative/aggressor knobs that retune the c-bet frequency and the post-flop lines.
  • Story. A villain's betting line implies a range. f$OppRepresents rates it on a 0–3 scale:
ScoreThe storyResponse
0No story — checked to you, no aggression yet.Play normally.
1Capped / weak — a tiny donk/min-lead, a float, or a station just betting anything.Attack: widen bluff-raises, floats, thin value.
2Merged / standard — one ordinary continuation bet.Call good, fold air. The default.
3Strong / credible — a 3-bet line, a check-raise, a turn/river raise, or a nit/passive player firing.Respect: fold marginal hands, no bluff-raise.

On top of that sits the range read (f$BeatenByOppRange / f$SafeVsOppRange). OpenPPL can't enumerate a custom combo range, so this is a practical made-hand-vs-represented-value read: their line + the board texture imply the top of their value range, and it asks whether your made hand sits above it. The literal 169-combo grid is what you see drawn per seat in the React table view's range grid.

And the opponent archetypes (10_opponents.ohf) come from PokerTracker HUD stats of the last raiser — VPIP, PFR, aggression factor, went-to-showdown — mapped to types like f$Opp_IsNit, f$Opp_IsStation, f$Opp_IsFish, f$Opp_IsLAG. The whole strategy then "plays the player, not just the cards": value big and never bluff a station, fold to a nit's aggression, attack a foldy player.

Feeler bets: betting to learn

🎯 The information bet

Sometimes you genuinely don't know where you stand — a marginal made hand, an unclear line. Rather than check blind or over-commit, Hiss fires a feeler bet: small enough to keep the pot controlled, but as large as it can be while still doing so, because the villain's response to that size feeds f$OppRepresents on the next street. f$WhereAmIUnsure spots the situation; f$FeelerBet fires it only when you can take a controlled stab (in position or holding the lead, never out of position into the aggressor); f$FeelerSize picks the size (half pot by default, ~1/3 on dry boards vs stations, ~1/4 multiway or very deep). On defense, a tiny (~1bb) bet into you is itself information — a capped/weak line read by f$Opp_MinBetLead — and cheap to call with any showdown value.

This is the through-line of the whole strategy: gather information, respect credible strength, attack weakness, and never go broke with one pair.

🏆ICM & lobby fetch

In tournaments the engine computes your dollar-equity for each line (CSymbolEngineICM) so short-stack jams and calls are $-correct, not just chip-correct. A lobby fetch reads the payout/game info page and posts it in. Sizing tightens near the bubble via f$SizeMult.

Talk to the bot. Your mic is transcribed offline (faster-whisper), categorized, pinned to the live hand, and stored. The improvement loop reads it first — losing-hand comments sorted to the top — so your spoken notes actually shape the strategy.

📡Replay / telemetry

EThe Autonomous Improvement Loop & its daemons

The AIL (Autonomous Improvement Loop) is a standing ~45-minute cycle that makes Hiss better on its own. It is a Claude Code cron job following a playbook (Release/logs/AIL_PLAYBOOK.md); each run makes one well-scoped improvement and writes a dated entry into the journal. Several helper daemons feed it — the AIL control server (mcp/ail_server.py, port 7900) starts/stops them and is the backend for the browser's AIL tab.

The synapse organism — signals feeding one mind

The loop runs in this order each cycle:

  1. Voice feedback first. Read your spoken notes (ail_feedback.py), losing-hand comments weighted to the top, correlated to the money result of the hand they react to.
  2. 1b · Harmonize the synapses. synapse_map.py recomputes the unified graph + the NN feature spec.
  3. 1c · Observational learning. observe_learn.py turns game state + HUD opponent stats into villain exploits and table reads (the observations table); it also drives the HUD aggregator.
  4. 2 · Review. Inspect recent decisions live and in the replay system.
  5. 3 · One improvement. Edit the OHF (validate then reload), or rebuild the C++, or fix a tablemap/setting — just one, well scoped.
  6. 4 · Verify, then 5 · Journal. Confirm with evidence, then write the dated entry referencing the voice-feedback ids acted on.

FGlossary

The terms a newcomer needs, in plain language.

OHF
OpenHoldem Formula — the strategy file. Your distilled poker knowledge as code.
OpenPPL
The language the OHF is written in: functions of WHEN … action … FORCE rules, evaluated top-to-bottom, first match wins.
f$Name
A function you defined (e.g. f$flop, f$Style). The f$ prefix marks it as a formula.
symbol
A built-in named value the engine computes, e.g. prwin, PotSize, AmountToCall.
list
A named set of starting hands (a range), e.g. listOpenBTN. A condition is true if your hand is in the list.
prwin
"Probability of winning" — your hand's equity, from a 20,000-iteration Monte-Carlo simulation on its own thread.
street
A betting round: preflop, flop, turn, river.
WHEN Others
The catch-all final rule of a function — the default when nothing above matched.
heartbeat
One pass of the main loop: scrape → OCR → symbols → (on your turn) decide & click → log.
scrape / OCR
Scrape = capture the table pixels using the tablemap regions. OCR = read text/cards out of those pixels (Tesseract, in worker processes).
tablemap
The per-site layout: where each card, bet, button and label is, plus colors and click config. Stored in postgres.
autoplayer
The component that turns a decision into a real mouse click on the right button.
aggressorchair / iamaggressor
The seat of the last raiser (remembered across streets), and whether that's you.
VPIP / PFR / AF / WTSD
PokerTracker opponent stats: % of hands voluntarily played, % pre-flop raised, aggression factor, % went to showdown. They classify opponent types.
SPR
Stack-to-Pot Ratio — effective stack ÷ pot. Low SPR means you're committed; high SPR means keep the pot small.
M / M-zone
Harrington's M = your stack ÷ the cost of one orbit (blinds + antes). Smaller M → push-fold sooner. The zones are Green/Yellow/Orange/Red/Dead.
ICM
Independent Chip Model — converts tournament chips into real dollar-equity, so survival counts when payouts are top-heavy.
c-bet
Continuation bet — betting the flop because you raised pre-flop, whether or not you connected.
NN
Neural Network — the trained alternate brain that can play in place of the OHF.
AIL
Autonomous Improvement Loop — the ~45-min cycle that reads feedback and makes one improvement at a time.
HUD
Heads-Up Display — the live overlay of opponent stats over each seat.
