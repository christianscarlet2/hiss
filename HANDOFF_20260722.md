## 1. Run ONE bot first — this is the next action

Nothing else should happen until a single bot plays a full orbit on a real NLH table.

```bash
ssh asterisk@192.168.1.39
cd /var/www/hiss-linux
HISS_LIVE_SUBMIT=1 HISS_FORMULA=strategy/ScarletBeast_linux.ohf ./build/hiss 18823
# then, against that port:
NN_BOT_URL=http://localhost:18823 NN_URL=http://localhost:8088/nn-decide \
  HISS_PG_DSN="$(sudo sed -n 's/^HISS_PG_DSN=//p' /etc/hiss-linux.env)" \
  python3 /tmp/nn_driver.py
```

**Watch three things.** Each is unproven, and each fails in a way that looks like something else:

1. **Does the first raise land at the intended size?** Amounts arrive from the driver in BIG BLINDS
   and are converted to chips in `hiss_action`. `bet.amount` = chips ADDED this street;
   `raise.amount` = TOTAL street commitment (raise-to). Confusing those two is the difference
   between a min-bet and a shove.
2. **Does the once-per-spot key release on the next street?** It is keyed `(hand, betround, seat)`.
   If live hand numbers do not advance the way the code assumes, the bot acts once and then
   silently refuses for the rest of the session — it will look "passive", not "broken".
3. **Does `ServerToAct()` ever match hero's seat?** Every test refused at this gate because it
   returned −1 with no real table. **The gate has never been observed to PASS.** If it never
   matches live, nothing will ever submit and the bot will look idle.

Kill switch: unset `HISS_LIVE_SUBMIT` and restart. Default is no-submit.

## 3. UNPROVEN — do not assume these work

1. **The live submit has never succeeded.** Every test was refused by a guard. Body format, server
   response handling, and the bb→chips conversion are all untested against the real API.
2. **`/decide` non-idempotency.** Seen ONCE: identical payload gave `raise (betsize 3)` then seven
   `call`s. 80/80 clean across three later stress patterns; never root-caused. Not OpenPPL history
   (`Raises`/`BotsLastAction` identical) and not memory symbols (`me_*` all 0). **Add per-decision
   logging before scaling** so a recurrence leaves evidence.
3. **The 666 oracle has never crossed its thresholds.** Verified off-by-default, in-range, and
   deterministic — but the box never got above ~55% load, so 0.50/0.66/0.80 and the decay path are
   untested. Leave `HISS_ORACLE` unset until tested.
4. **The odometer guard has never fired in production.** Live but has not seen a real table switch.
5. **`max_replication_slots`** raised 10→40. The leak that ate the first 10 was a permissions bug
   (now fixed); confirm slots stay near zero after a day rather than assuming.

## 4. Traps that cost time today

- **The active strategy tree is `.strategy_build/strategy/*.ohf`**, NOT `Release/bot_logic/Strategy/`.
  Validate with the `validate_ohf` MCP tool (real OpenPPL grammar). `build_and_lint.py` writes the
  master; `HISS_MASTER_OUT` stages without clobbering the live file.
- **In `.ohf`, `\` continues a `//` comment — it cannot START one.** A `\` line right after a
  `##header##` is parsed as CODE.
- **`hand_results` was fabricated for a whole afternoon.** One connection alternating between two
  tables logged every balance flip as a hand. 175 "hands" in the 17:00 hour, losses cancelled by
  wins. Any results-based analysis before today's cleanup is suspect.
- **The bot was attached to a Google Chrome window for ~4 hours** (15:00–19:00), including a LinkedIn
  tab, via a recycled HWND that `::IsWindow()` still considered valid. `CAutoConnector` reported
  "table candidates: 0" throughout — it was the pin path, not tablemap matching. **Still unfixed.**
- **`LogDecision` had exactly one call site** (`ExecuteRaiseCallCheckFold`), so all-ins and keypad
  bets never reached the DB. Partly fixed; needs the link.
- **`server.cpp` parsed the request line with `%255s`.** `nn_driver` asks for ~86 symbols in one
  query string; everything past 255 chars was silently dropped and returned 0, so the NN decided on
  a blank pot. Now 4 KB. Watch for other fixed-size buffers on that path.
- **Do not dedupe `hud_player_stats` on `player`.** It is legitimately keyed `(player, gametype)` —
  one nlhe row + one plo row per player. swiftsnake had a stale `UNIQUE(player)`; that was the bug.
- **Logical replication does not pick up tables created after the subscription**, even with
  `FOR ALL TABLES`. Needs `ALTER SUBSCRIPTION ... REFRESH PUBLICATION`. Check for PK collisions on
  the subscriber FIRST — a conflict kills the whole subscription, not just that table.
- Windows-side heredocs: a Python `\n` inside a bash heredoc becomes a literal newline inside C
  string literals → `C2001`. Use the Edit tool or scp a patch script.
